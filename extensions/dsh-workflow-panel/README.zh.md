# Workflow 运行面板

[English](README.md) | 中文

## 概述

这个独立的 Cordis 扩展在侧栏添加页面，读取 `<rootDirectory>` 下社区 `@dsh-external/workflow` 插件的 `.dsh/workflow-runs` 运行存储；挂载 CPIC 需求服务时，还会自动聚合其持久化的案例设计运行。页面按时间倒序显示状态摘要和运行详情，包括 CPIC 阶段进度及允许读取的 JSON 产物。社区运行保持只读。可恢复的案例设计运行可通过 CPIC 重试，CPIC 仍是权威数据来源；面板不会伪造 workflow 存储文件。页面还提供新建运行使用的案例设计流水线模板，支持查看与编辑。

<a id="activate"></a>
## 启用

仓库的[多用户 gateway 启动器](../../scripts/multi-user/README.zh.md#windows-web-deployment)通过专用补丁，为 gateway 拥有的租户进程挂载本源码。社区 workflow 插件用于文件存储的运行记录，必须安装；CPIC 为可选来源，挂载 `cpicRequirements` 服务后会自动显示案例设计运行。更改启动组合后，须重启 gateway 及其拥有的租户进程，再刷新已认证的 gateway 页面。任何 Loader 组合都可用同样方式挂载本扩展：以绝对文件 URL 注册 Host 模块，并让 `client.js` 与它同目录。包清单必须声明 `dsh.client`（`platform: web`）并导出 `./client`；客户端模块扫描依据该声明发现 bundle 并以包名作为键，因此 `client.js` 内 `__ModuleLoader__.load` 的 id 必须等于清单的 `name`。

<a id="use-the-panel"></a>
## 使用面板

侧栏按钮打开 workflow 页面。列表合并社区 workflow 运行与已挂载 CPIC 服务的案例设计运行；案例设计行会显示来源和已提交阶段进度，无需另行输入命令。工作区下拉框可筛选列表；文件运行会按存储目录匹配已注册工作区。每次请求都读取当前已挂载的工作区和 CPIC 服务，包括在面板之后挂载的服务。运行按工作区和可识别的会话分组，会话组按组内最新运行时间倒序，组内运行也按开始时间倒序。会话标题使用租户当前可读取的活动或持久化会话名称；刷新后可看到重命名。会话查询服务不可用或标题为空时，标题回退显示会话 ID。缺少会话 ID 的旧记录会各自按时间排列，不显示虚构的会话标题。点击社区 workflow 运行可查看 manifest、进程图、有成本指标时显示的成本、产物，以及最新记录事件的时序图。只有记录了可识别任务信息的 Agent 启动、完成和消息事件，才会画出 Workflow 与 Agent 之间的箭头；其他事件显示为 Workflow 时间线标记。图按事件顺序呈现，不推断记录中没有的调用关系。带版本号的流程图展示快照中记录的 Workflow 包含关系、阶段成员关系，以及由 `task_id:` 输入声明的任务间证据引用；不会把引用任务画成调度前置条件。旧快照仍显示原有进程条目列表。流水线模型之前的案例设计详情以四阶段有向图显示阶段顺序，携带流水线定义的运行改为显示六个流水线节点（见下文）；事件列表从持久化的阶段尝试和评审检查点重建，不包含未记录的时间戳或模型交互细节。产物以可换行的浮动按钮排列，点击后在按钮区下方预览。刷新会重新读取所有视图，并在可用时重新核对当前 workflow 引擎。当前引擎仍持有的运行会继续显示运行中；当前进程启动前留下、且已没有活动引擎持有者的持久化运行会显示为已中断。无法安全匹配的运行会显示为状态待确认，不会直接当作已停止。已中断表示当前进程不再拥有该运行，不代表独立调度的工作进程也已结束。详情标题突出显示 Workflow 名称和开始/结束时间。运行列表和详情元信息会分别标注已启动与运行中的子 Agent 数量。

Workflow 页面还在运行列表之外提供“流水线配置”入口。展开后读取新建运行使用的模板，按顺序列出六个流水线节点及其阶段、执行角色、工作区、绑定 Skill 与 Judge 规则。点击节点可在面板内编辑执行角色、Skill、工作区以及 Judge 角色与规则；点击“保存”把编辑后的定义提交给 CPIC 服务，并用保存结果刷新显示。保存失败时编辑内容保持不变并显示本地化错误，“保存”按钮即为重试。挂载的 CPIC 服务不支持流水线配置时，入口显示不可用状态并提供“重试”，页面其余功能不受影响。保存的修改只影响新建运行。

运行详情保持打开时，面板每 2.5 秒读取其持久化快照，两次读取之间保留最近一次成功加载的详情；终态快照停止轮询。带流水线定义的案例设计详情按顺序把节点显示为执行卡片：节点标题按 id 映射到本地化字典、未知 id 回退显示 id 本身，另有状态标记（完成、进行中、阻塞、未开始、待确认）、尝试次数、最近一次 Judge 结论及其问题列表、阻塞节点的阻塞原因、已提交产物名称。点击节点可展开该节点的核验记录（含执行角色、Skill 与 Judge 角色）和输出产物（用 JSON 键值树展示，并可展开原始 JSON）。阻塞节点以醒目样式显示状态标记和阻塞原因。没有 pipeline 字段的运行以及 pipeline 缺失或字段不完整的记录仍显示旧的四阶段视图。版本 2 的进程图按记录的 `node:<id>` 链展示 `next` 边；版本 1 的图保持原有包含关系展示。运行列表中 blocked 状态的条目显示本地化的“已阻塞”标记和阻塞摘要，案例设计“重试”入口仍只对 pending、failed 和 cancelled 状态开放。

JSON 结果摘要会以带连接线的键值树显示，支持嵌套对象和数组；需要时可展开查看原始 JSON。非 JSON 摘要仍以普通文本显示。

所有案例设计运行详情均提供“溯源分析”。报告使用该次运行的不可变快照与已提交的需求整理、功能点、场景和用例，而不是需求当前正文。有向图展示每个已提交条目，并为相邻阶段的每条实际引用显示箭头。点击条目会高亮其跨阶段祖先与后代，不会高亮同阶段的兄弟条目；其他阶段列会自动定位到该列第一个高亮条目，被点击条目所在列保持原位。后续阶段尚未提交时标记为部分溯源。租户本地 CPIC 服务只读分析，不发起模型请求或修改记录。查询失败时保留运行详情，并提供独立重试入口。

案例设计运行处于 pending、failed 或已停止（cancelled）状态时，点击“重试”会请求 CPIC 从当前已保存的检查点执行一次 advance。已取消的运行仅在原会话（Session）仍由 Host 中的活动 agent 持有时才能恢复，已保存的阶段数据保持权威。该操作可能生成或评审一个阶段并消耗模型 token，不会执行所有剩余阶段。成功后，详情会替换为 CPIC 返回的权威详情。失败时保留当前显示的详情并显示本地化错误；可点击“刷新”查看最新持久化状态。

<a id="configure-the-source"></a>
## 配置来源

Host 模块接受三个字段。`rootDirectory` 是面板读取社区 `.dsh/workflow-runs` 的绝对目录，覆盖根目录与下一层项目分区两种位置；补丁将其设为各租户进程的工作目录。CPIC 运行从已挂载的 `cpicRequirements` 服务读取，不依赖该目录。`maxEvents` 限制每次 workflow 详情请求返回的事件数（默认 500，文件更长时保留最新部分）。`maxRuns` 限制合并后的运行列表条数（默认 200，保留最新）。文件操作保持只读，并在打开文件前校验运行 ID 和产物路径。案例设计重试委托给已挂载的 CPIC 服务。

<a id="execution-and-storage"></a>
## 执行与存储

每个操作经租户已认证的 HTTP 路由返回 JSON。社区运行从文件读取；CPIC 摘要和阶段详情从 CPIC 服务读取，不暴露需求正文或存储路径。若社区快照仍标记为 running、但事件日志已有 workflow 终止事件，面板会显示终止状态并将活动 Agent 数量置零，不修改存储文件。当前 workflow 服务可用时，刷新会查询对应工作区引擎：引擎仍持有的运行以引擎快照为准；引擎已有终态时以该终态覆盖文件快照；当前进程启动前的快照若已没有引擎持有者，则显示为已中断。运行时状态缺失或无法识别时显示为状态待确认。CPIC 产物请求仅接受该运行记录的 JSON 文件，并限制读取大小为 1 MiB。workflow 运行目录缺失时文件来源返回空列表；不可读的 workflow 快照会从列表跳过，无法解析的事件行不会让请求失败。社区 workflow 的产物路径必须留在其运行目录内。流水线定义经 CPIC 服务读写，服务校验后一次性保存完整定义，校验失败不会部分生效。仅当 pipeline 的每个展示字段都存在且类型正确时详情才携带该流水线，字段不完整的记录回退到旧的阶段视图，不会报错。

## 验证

从仓库根目录运行 Host 组合测试、浏览器模块测试和租户补丁回归测试。下列命令中的进程内 TypeScript 源码加载器是测试夹具，不是应用启动器。

```powershell
node --import ./extensions/cpic-requirements/tests/fixtures/source-loader.mjs --test --experimental-test-isolation=none extensions/dsh-workflow-panel/tests/*.test.js
node --test scripts/multi-user/workflow-panel.test.js
```

Host 测试使用真实 Loader 和共享 fetch 处理器驱动夹具存储及 CPIC 服务，覆盖列表排序、事件尾截断、运行 ID 拒绝、产物路径校验、项目分区聚合、CPIC 列表/详情/产物路由且不复制文件、流水线配置读写路由且失败不部分生效、流水线详情防御读取、客户端模块发现和无效客户端 bundle 声明。浏览器测试断言 workflow 与案例设计列表标记、阶段进度、图节点和证据引用边、旧进程条目展示、详情、产物预览和错误状态，以及流水线配置编辑与保存重试、六节点状态与阻塞展示、节点展开 checks 与 output、旧运行回退和版本 2 运行图。租户补丁回归测试用 jsdom 驱动同一客户端 bundle。

<a id="model-experience"></a>
## 模型体验

面板不注册面向模型的工具，也不新增会话事件类型。浏览和刷新不会发起模型请求或产生 token 成本。查看或编辑流水线配置不发起模型请求。显式重试案例设计会执行一次 CPIC advance，可能启动生成或评审 subagent，并沿用 CPIC 已有的会话日志及模型/token 成本。

<a id="known-limitations"></a>
## 已知限制

社区 workflow 文件只读取一个 `rootDirectory` 及其下一层项目分区；CPIC 运行受限于已挂载租户服务可见的记录。面板不流式刷新，点击刷新后重新读取持久化数据，并在 workflow 服务可用时核对当前引擎。CPIC 事件视图根据已保存的阶段尝试和评审检查点重建，不包含时间戳或详细模型交互；CPIC 也不提供模型成本统计。社区事件视图保留最新 `maxEvents` 条记录，不提供更早记录的翻页。产物预览只渲染 JSON，不重新执行脚本。社区运行仍由其现有工具控制。案例设计重试不能协调结果不明的存储状态，也不能重启已完成的运行。已取消运行只能从已保存的检查点恢复，且原会话（Session）须仍在 Host 中拥有活动 agent。流水线配置编辑只修改已加载模板的执行与 Judge 字段，且只影响新建运行；面板不能新增、删除、排序或改绑节点，已有运行保留启动时记录的流水线快照。
